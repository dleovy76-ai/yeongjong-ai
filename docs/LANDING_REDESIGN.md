# 랜딩 페이지 리디자인 (2026-08-26)

## 배경

Cowork(Claude)와 함께 랜딩 페이지(`/`)의 시각 디자인을 재정비했다. 기존엔 Tailwind 기본값만
쓰는 흑백 텍스트 페이지였고(`tailwind.config.ts`에 커스텀 테마 없음), 정해진 색/폰트가 전혀
없는 상태였다.

세 가지 방향을 스케치해서 오너가 골랐다.

- A. 차분한 신뢰형 — 세리프 헤드라인 + 짙은 네이비/티얼
- B. 따뜻한 로컬 무드 — 크림 + 코랄 + 해변 실루엣 **(채택)**
- C. 미니멀 테크 프로덕트 — 화이트 + 코발트 포인트

## 변경 파일

- `frontend/tailwind.config.ts` — 색상 토큰(`cream`, `coral`/`coral-dark`/`coral-darker`,
  `ink`, `ink-muted`, `sky`, `terracotta`)과 폰트 토큰(`display` = Gowun Dodum, `sans` = Noto
  Sans KR) 추가. 앞으로 다른 화면을 디자인할 때도 이 토큰을 재사용할 것 — 색상 하드코딩하지 말 것.
- `frontend/app/globals.css` — 구글 폰트 import(`Gowun Dodum`, `Noto Sans KR`) + body 기본
  폰트.
- `frontend/app/page.tsx` — 랜딩 히어로 전면 재작성. 태그 칩("영종도 로컬 AI"), 헤드라인, 파도+태양
  SVG, pill 버튼 2개. 모바일/데스크톱 하나의 반응형 컴포넌트로 작성(별도 모바일 컴포넌트 없음).
- `frontend/components/NavBar.tsx` — 워드마크와 기본 CTA 버튼("우리 가게 AI 만들기")만 코랄로
  변경. 나머지(로그인, 로그아웃 등 텍스트 링크)는 손대지 않음.

## 확인된 이슈 (수정 완료)

데스크톱 브라우저에서 실제 확인했을 때, 헤드라인 두 번째 줄("영종 AI가 나머지를
도와드립니다")이 컨테이너 폭 부족으로 한 번 더 줄바꿈되어 "다."만 세 번째 줄에 혼자 떨어지는
버그가 있었다. `h1`의 `sm:max-w-2xl` → `sm:max-w-4xl`로 수정, 커밋 완료. **브라우저에서 실제로
두 줄로 딱 떨어지는지 재확인 필요** — Cowork 세션에서는 로컬 브라우저로 재확인할 방법이 없었다.

## 확인/결정 필요 (Claude Code가 직접 볼 것) — 2026-08-26 처리 완료

1. ✅ 헤드라인 줄바꿈 — 브라우저에서 JS로 실제 줄 수 측정까지 해서 확인. 데스크톱(1280px)
   2줄 정상.
2. ✅ 모바일(390px) 확인 중 **문서에 없던 버그 2건을 새로 발견해서 같이 고쳤다**:
   - 헤드라인이 모바일에서 "도와드립니다" 단어가 "도와"/"드립니다"로 쪼개져 줄바꿈되는
     문제 — 데스크톱에서 고친 것과 같은 성격의 버그였는데 모바일 쪽(`max-w-xs`)은 안 고쳐져
     있었음. 근본 원인은 두 경우 다 한글 줄바꿈이 단어 중간에서 일어나는 것이었어서,
     `max-w` 숫자를 더 조정하는 대신 `break-keep`(word-break: keep-all)을 h1/p에 추가해
     앞으로 이 종류의 버그가 재발하지 않게 했다. 모바일은 이제 "영종 AI가 나머지를" /
     "도와드립니다."로 깨끗하게 3줄 word-boundary 줄바꿈.
   - `NavBar.tsx`가 반응형 처리가 전혀 없어서 390px에서 "로그인"→"로그"/"인" 등 글자가
     단어 중간에서 깨지던 문제 — `flex-wrap` + `break-keep` + 모바일 텍스트/패딩 축소로 수정,
     이제 한 줄에 깔끔하게 들어감.
3. ✅ NavBar 코랄 색상의 나머지 화면(대시보드·성과·관리자 등) 확대 적용 여부 — **이번엔 보류**로
   결정. 이유: (a) 지금 최우선 과제는 실제 파일럿 실행이지 시각 디자인 통일이 아님(이 문서 위
   "배경"에 인용한 결론과 동일), (b) 여러 화면에 걸친 리브랜딩은 이미 동작 중인 화면들에 회귀
   위험을 만드는 규모가 큰 작업, (c) `tailwind.config.ts`에 토큰은 이미 만들어져 있으니 나중에
   특정 화면을 다시 손볼 이유가 생기면 그때 그 토큰을 재사용하면 됨 — 지금 미리 전체를 바꿀
   필요는 없음.
